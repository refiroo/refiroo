# Behaviour rules inventory

Rules that decide what a person can and cannot do with data and models, and that no screen presents as a
feature. Each shows only as a missing or locked control, a value that cannot change, a refused save, or a
deletion that takes other records with it.

Columns: **Rule** (plain words) | **Cause** (model key or engine condition, `file:line` under `backend/app/` unless
a path is given) | **Effect** (what a person can / cannot do) | **In the UI** (control behaviour, exact text) |
**Reader** (St = steward, MA = model-admin, AA = access-admin / security admin, WA = workspace admin, Int = integrator via API) |
**Code** (API error, `status CODE`). **Source** names the ADR / release / decision where one states the rule.

Coverage note (what was and was not read): see the last section. Every row below was confirmed in code or in
`docs/APPLICATION_MODEL.md`, `docs/DECISIONS.md` (ADRs) or `CHANGELOG.md` text; rows that rest only on a
changelog/ADR statement say so in Source.
