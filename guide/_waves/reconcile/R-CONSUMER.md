## Code checks and disagreements

- Consumer authentication: `backend/app/consumer/router.py::_authenticated` exempts definition OpenAPI documents; it accepts both audiences for the index, with different visibility. Older source paragraphs require a document token or allow consumer grants for people/groups. `engine/authorization/administration.py` restricts those grants to clients.
- Schema window: `engine/model/compiler.py::SCHEMA_VERSIONS` contains only 0.10. Older source sections say stored 0.8 releases still activate/read; current code requires raising eligible releases first.
- Version overlap: COMPATIBILITY.md promises old consumer versions remain served beside new ones. Current definition resolution serves the workspace’s one declared live version. Documented the implementation limit and retained the commitment as a separate promise; this is an unresolved product/code gap.
- Draft comparison: `management/routers/model_management.py::get_model_draft_consumer_api` passes `base_model`, whose fallback is the newest release of the same model. Several older source passages say active release. Activation still compares with the chosen workspace’s current release.
- Changed outputs: later consumer-source amendments and event code use recorded source names, not a rendered before/after comparison. Watches can fire while an answer remains equal.
- API names in errors: the older source says no error carries the consumer API name; FORBIDDEN details do. Names are public, not credentials.
- API.md says unique-value database enforcement is planned; `engine/indexes/unique_values.py` and migration `20261007_07_unique_attribute_values.py` show the existing constraint/trigger boundary. The guide states the enforced rule without repeating that obsolete implementation claim.
- Historical host-allowlist, coalesced webhook, create-only JSONL export and same-policy preview designs are superseded within the source itself. Current defaults and behavior were used. `PUBLIC_URL` exists although an old CloudEvents explanation says there is no public base-URL setting; the emitted CloudEvents source remains relative.
- Guide corrections: generated per-type event names are `<type-key>-changed`, not consumer.created/updated/deleted. Whole consumer-API removal is a warning, not a blocking error. Model-admin pages no longer show JSON bodies or API paths.
