# UI inventory: data work (what a person can do with records, change sets, jobs and moves in the browser)

Source: `frontend/src` read 2026-11-02 (read-only; not run against a live instance). Paths are under `frontend/src/` unless stated.
Format follows MODEL-EDITOR-INVENTORY.md (that file covers the model editor; not repeated here). "ai-later" = 0.16 AI feature (ask in words, proposals, assistant, explain). Line numbers marked "~" are from reading, not exact.
Abbreviations: APP = `app/App.tsx`, SHELL = `app/AppShell.tsx`, BAND = `app/DataContextBand.tsx`, TOP = `app/TopBar.tsx`, ACC = `app/SettingsMenu.tsx`, CV = `features/objects/CollectionView.tsx`, OD = `features/objects/ObjectDetail.tsx`, OT = `features/objects/ObjectToolbar.tsx`, FB = `features/objects/filters/FilterBar.tsx`, CS = `features/workspaces/ChangeSets.tsx`, CSR = `features/workspaces/ChangeSetReview.tsx`, PUB = `features/workspaces/Publications.tsx`, WS = `features/workspaces/`, JOBS = `features/jobs/`.
"Needs" column uses the action-group names exactly as the Account/People pages show them (backend `engine/authorization/catalogue.py:27-110`): Browse, Edit live, Work in change sets, Publish, Approve publications, Bulk and import, Copy and move, Model authoring, Model release, Workspace administration, Operations, Security administration. "Jobs on" = the deployment lets jobs be created (`capabilities.integrationJobs.createJobs`; otherwise import/export/cancel/bulk are not offered).

- No global keyboard shortcut list or command palette; no "/" or Cmd+K search; no in-app Help page or Help menu (About page only links to the documentation and API reference, features/settings/AboutPage.tsx:54-57).
- No point-in-time or "as of" browsing of records in the application: only the export has "Valid on", and a record's History is a list of changes, not a view of an earlier state. No restore/revert of a record or value from History; no undo of data edits (undo/redo exists only in the model editor and the mapping editor).
- No History panel inside a change set or a publication (OD:~430 draws it only in Live).
- No saved views, saved filters or saved searches (only the address and per-device Display settings); no multi-column sort; no column reordering in Display (visibility, density, widths, page size only); no grouping/aggregation; no cross-collection search page (search is per list and in the explorer rail).
- No row-creation inside the table, no duplicate/copy-record action, no paste-from-spreadsheet, no merge of records.
- Bulk actions exist only on the table lens selection (Change values, Change relationships, Delete); none on mapping grids, matrices, trees (trees only move several nodes), relation panels or notifications beyond their own bar. No bulk export of a selection (export takes the list's filters, not its ticked rows).
- No rename of a change set after creation, no comment thread on a change set (only the Submit comment and the decision comment), no diff between two change sets, no partial publish (publish takes the whole change set), no "reopen" of a published change set (a published change set is gone; use "Start a change set from this publication").
- No delete or edit of a publication; only "Withdraw publication" and "Start a change set from this publication".
- No notification for failed imports to other people; no per-notice link for "approved"/"published" notices (they lead nowhere).
- No download of the refused rows of an import from the job page (rows are listed on screen; not established whether a download exists beyond `Download` for exports).
- Import never offered in a publication or a retired workspace; Export is offered everywhere the deployment runs jobs (including publications).
- Home has no export/import, no search; the Changes page has no free-text search.
- Tree lens, mapping grid and matrix views are only what the model declares (the browser cannot create or edit those views; that is the model editor).
