title: Open an application
description: Choose a workspace, open an application and select a view of its records.

---

Open the right data before searching or editing. See
[Applications](/docs/use/applications/) and [Workspaces](/docs/use/workspaces/) for how models,
datasets and views fit together.

## Start from Home

1. Select the refiroo name in the top bar to open Home. Under **Your workspaces**, find the
   intended workspace. Check the model name and release on its card; similar workspace names
   do not guarantee the same data or structure.
2. Choose the workspace’s name or tile to open its page, then choose an application. Its
   default view opens in that workspace. The application names come from the model. An
   application link on the Home card opens that application directly.
3. Check **Workspace** in the sidebar and the context banner above the records. Choose **Live**
   for current data, or open the intended change set or publication. A publication is read-only;
   Live saves apply immediately.

![Home showing workspace names, model releases and application buttons](/docs/screens/workspaces-home.png)

*Above: Graubünden offers Network, Systems and Names. Default offers RDM Master, RDM Systems
and RDM Translations under a different model.*

If no workspace is offered, ask an administrator for **Browse** access. If Home reports a loading
failure, retry it before concluding that no workspaces exist.

## Choose a collection and view

1. Select an application in the top bar, using **More** if it does not fit. On a phone,
   choose it in the band beneath the top bar. Read its sidebar collections; switching applications
   can change which collections are offered. If a collection group is folded, expand it.
2. Choose the collection you need. Check the page heading and description.
3. If tabs appear below the heading, choose the view that suits your task. A table helps
   [find records](/docs/guide/use/find-records/); a tree helps
   [arrange records](/docs/guide/use/arrange-records-in-a-tree/); a mapping grid helps
   [map records](/docs/guide/use/map-codes-between-systems/); a relation matrix helps
   [check coverage](/docs/guide/use/fill-in-a-relation-matrix/).
4. Check the banner again before changing anything. Opening an application or changing a view
   does not itself save a data change.

![An application with multiple views of the selected collection](/docs/screens/app-systems.png)

*Above: System codes in Systems has a table and the Codes to stops and Codes to municipalities
mapping tabs. Other collections can offer different view kinds.*

A missing view may simply not be declared by the model. Ask a model administrator about the
intended configuration. An empty collection means there are no matching records in that context;
a reported loading error needs a retry instead.

## Switch workspace

Follow [Switch workspace](/docs/guide/use/switch-workspace/) to choose another dataset and check
its model, applications and context before editing.

## If the address does not fit this workspace

After switching, read the toast if the model or release differs. An old bookmark can open
**Not in this model**: the named application, collection or type is absent here. Choose one of
the offered workspaces whose model has it, or return Home and open an application this workspace
provides. If the workspace itself cannot be served, read the displayed reason and ask the
operator for help. Other workspaces remain available. A retired workspace can be opened through
**Settings › Workspaces** where permitted, but stays read-only.
