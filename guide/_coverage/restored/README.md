# Coverage

What the guide must account for, and the check that nothing is missing (plan 0.13, "Coverage"). This
folder is not published.

- `inventory.json` is generated by `npm run inventory` (`tools/inventory.py`, which reads the sources of
  truth: CURRENT_FUNCTIONALITY, USER_JOURNEYS, the settings catalogue, the error codes the backend raises,
  `app/cli/`, the permission catalogue, the event types and the model-language schema). Run it again when
  any of those changes, and commit the result. The kinds, their item IDs and their sources are in the
  script's header.
- `exclusions.yaml` lists the items the guide does not cover, each with a reason. It may only shrink.
- A page lists the items it covers in its front matter (`covers`); a brief lists the items its page is
  to cover. `npm run check:coverage` reports, per kind, how many items are excluded, covered by a written
  page, assigned to a brief, owned by wave G (0.16's, written after its release step) or still without an
  owner; it fails on an item named that does not exist, an exclusion without a reason, and a page that
  leaves out a statement its brief requires (`must_state`). `npm run check:coverage -- --strict` also
  fails while any item is neither covered nor excluded: the release gate.

- The `docs` test group fails when `inventory.json` differs from a fresh generation
  (`test_the_coverage_inventory_is_fresh`): run `npm run inventory`, assign any new item to a page (or, if
  it is 0.16's, to `wave-g-items.txt`), and commit the file.
- Every page has a brief in `_briefs/<section>/<page>.md`; a stub brief (`brief: pending`) holds the page's title,
  kind, reader, wave and the items it owns. Stubs live in `_briefs/`, not in `src/content/docs/`, because the
  build refuses a published stub.
