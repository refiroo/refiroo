# Missing-address page evidence

Starlight 0.42.8 injects its explicit /404 route in dist/index.js. The collection route also generates the 404 content entry, explaining Astro's duplicate-route warning. Its routes/static/404.astro renders CommonPage; utils/routing/data.js:get404Route explicitly loads the user's docs entry 404.

The built _build/C11-FINAL/404.html contains our introduction and Search this guide and Browse a section headings. A FastAPI TestClient mounting the actual app.management.guide_site.GuideFiles class over this isolated output returned HTTP 404 for /docs/c11-address-that-does-not-exist/, our exact introduction/search guidance, and the guide security headers. No listening server or database was started. This verifies the serving component, not a deployed reverse proxy.

Removing the warning cleanly requires route/build configuration outside the allowed files. Marking the content draft would remove its ordinary route but also display a draft-content warning on the custom fallback; renaming its slug would prevent Starlight from finding the custom 404 entry. Neither workaround was applied. No configuration file was edited.
