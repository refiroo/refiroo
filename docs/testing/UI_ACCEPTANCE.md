# UI acceptance

**Package:** Base 0.7 WP-13C, 2026-09-24. **Inputs:** the [coverage map](COVERAGE_MAP.md) (C-UI-*,
C-MAP-UI, C-DR-PIN) and the [execution guide](EXECUTION_GUIDE.md). **Consumers:** every package that
adds or materially changes a user-visible surface, and WP-9.

This document answers two questions: *which existing screen must my new UI look and behave like?* and
*which states of a changed surface have browser evidence, and which do not?* Accessibility checks and
screenshot equality supplement design review; neither establishes that a layout is good. An
uninspected appearance is unverified, not passed.

## 1. Reference patterns

Reuse the named reference's structure, classes and tokens. Introduce a shared component only when a
repeated gap is demonstrated on two surfaces; do not add a second design system or redesign a surface
to fit a new control.

| Pattern | Reference (0.6, retained in 0.7) | Structure to reuse |
| --- | --- | --- |
| Dialog | `ui/Modal` as used by `features/objects/ObjectFormDialog.tsx` | `Modal` (title, optional `eyebrow`, `busy`, `dirty`, `size="compact"` for short forms) wrapping one `<form>`; `Notice` for the error; `.dialog-actions` with Cancel (`secondary`) then the submit (`primary`). Never a hand-rolled `.dialog-backdrop`. |
| Confirmation | `ui/ConfirmDialog` (change set publish/discard, deletion) | States the consequence; destructive action uses `danger`/`danger-ghost`. |
| Field | `ui/AttributeField`, `ui/ObjectLookup`, label-wrapped `<input>/<select>` in `ObjectFormDialog` | Visible `<label>` text wraps the control; required state from the model; typed input types. Checkboxes and radios are drawn from the tokens in `base.css` (control border, the primary action when checked, faded when disabled; UA7), so they follow the theme; never style one locally. |
| Actions | Page header action (`ui/PageHeader` `actions`, one `.primary`), `RecordActionMenu`/`ui/ActionMenu`, `ui/ControlPopover` | One primary action per surface; secondary actions in a menu or `<details>` disclosure; icon buttons carry an accessible name. `ControlPopover` is non-modal: a press outside closes it and acts (UA0). |
| Page surface | `features/objects/CollectionView.tsx` | `ui/PageHeader` (title on the 30px step, description, actions; 0.9 U2); `ui/Card` (flush, U-D8; the `.surface` panels moved onto it in UA6) with toolbar and a continuous list. |
| Shell and data context (0.9 U2) | `app/ShellFrame.tsx`, `app/TopBar.tsx`, `app/AppShell.tsx`, `app/DataContextBand.tsx` | One frame and one top bar for every area (U-D14): the top bar (mark to home, application tabs, the **Settings** link and the **Account** popover; U3), the rail with the explorer, and the band naming the data: Live (green `ui/StatusPill`), a change set (amber band with its own bar) or a publication (violet). A context's reports go below the band (`ui/ContextBandSlot`). An application tab and a rail collection carry a `ui/HueTile` in the hue `model/hues` gives it by position (ADR-040). Status is a `StatusPill` (marker and text); a value is plain text. Colours come from the semantic roles in `styles/tokens.css`, never from primitives. |
| Settings layout (0.9 U3; Integration's pages U4, Webhooks U5) | `app/SettingsShell.tsx`, `features/settings/DeploymentPage.tsx`, `features/workspaces/WorkspaceAdmin.tsx` | The shared frame and top bar (`ShellFrame`, `TopBar`; no application current, **Settings** the current tab with its name and underline), without workspace or data context; rail `nav aria-label="Settings"` with group headings and `aria-current` links, in the navigation drawer below 760px (a **Settings: {page}** bar opens it). Each page is `ui/SettingsLayout` (group as the eyebrow, the application pages' width) with ruled `ui/Section`s; facts in `ui/DescriptionList`; tables as a labelled, focusable group that stacks row by row below 760px; loading as `ui/Skeleton`; nothing to list as `ui/EmptyState` with its action; form fields as `ui/FormField`; a completed write confirmed by `ui/Toast`, errors inline. Workspaces, Model and Webhooks: the catalogue beside the selected entry's card (`ui/CatalogueLayout`, `CatalogueEntry`), each entry at its own address; below 760px they take turns, with a back button (U-D10 as revised). |
| Continuous list (0.8 S5) | `ui/ScrollWindow` in `ui/ObjectTable` (collection lens) | Labelled scrolling region with a sticky header; quiet start and end markers; the scroll space spans the whole list and the browser's own scrollbar is the list's (0.11 X6); a row whose page has not arrived is a loading row at its place, hidden from assistive technology; footer with the visible range, page field, start/end buttons and, where the list seeks, a **Go to** field. Rows carry `aria-rowindex` and the table `aria-rowcount`. |
| Tree (0.8 S6) | `features/objects/RecordTree` in the explorer's **Browse records** | `role="tree"` with one tab stop. Each object type's records form a group headed by an item naming the type (opening its collection; its count is in its accessible name only), drawn as a quiet label, never like a record; every record shows its type's `ui/HueTile` and the selected one is filled with its type's soft colour; an open branch starts below its record's toggle, and a group's frame shows only while its window scrolls (ADR-040, UA2); the rows scroll in a bounded `ui/ScrollWindow` whose viewport is the named `group` (a tab stop only while it scrolls, presentational edge markers, announcements through the tree's one live region). `aria-level`, `aria-setsize` and `aria-posinset` from totals; Up/Down cross window edges by loading, Right/Left expand, enter, collapse and return, Home/End, Ctrl+Home/End within a group, Enter opens. |
| Table sort (0.8 S4R3) | Record panel header sort: `CollectionPanelTable` over `ui/ObjectTable` and `RelationsPanel`, both drawn by `ui/DataTable` (UA4 revision), through `ui/TableSort` | Every data column sorts from its header (quiet icon on hover/focus drawn in the header padding, accent arrow when sorted, toggle on activation, `aria-sort`, name stating the order, polite announcement); only Actions, the computed path, JSON and unrecorded timestamps do not. Every list with sort fields carries the same icon-only `ui/ActionMenu` Sort menu in its toolbar (radio fields plus direction, tooltip). No labelled sort select or popover. |
| Column widths (0.9 UA4 revision, UA7) | `ui/DataTable` with `onColumnWidths` (`ui/TableDisplay` stores them) | Columns lay out by content until one is sized; then every width is fixed and the actions column takes the difference. Each column's `ui/ResizeHandle` (`separator`, arrows, Shift for larger steps, Home/End) stands in one sticky layer before the table, at the column's measured right edge, never inside the header cell, so a header's name is its label alone. Hidden below 760px. |
| Load failure | `ui/InlineError` (a `Notice` titled “Could not load this content” with **Retry**) | Replaces only the failed content; shell, header and previously loaded data stay; Retry repeats the exact request. |
| Empty state | Collection empty row (`ui/EmptyState` in `ui/ObjectTable`), `.empty-panel` in `ChangeSets` | Says whether nothing exists or nothing matches the current search/filter. A collection shows its type's tile above the message, and **Add {type}** when nothing exists and the user may write; a narrowed list's way back is the toolbar's **Clear filters**. While the first page loads, the table shows six rows in its own shape and one status. |
| Notice | `ui/Notice` tones `info`/`warning`/`error` | Title plus a sentence stating what happened and the safe next action; `focusOnMount` for a failure the user must act on. |
| Disclosure | `<details>` in `ChangeSets` (More change set actions) and `ModelReleaseDetail` (Technical details); `ui/Tabs`; `ui/NavigationDrawer` | Native keyboard operation; identifiers and technical metadata stay collapsed by default. |
| Narrow layout | `styles/responsive.css` at ≤ 720px; 390×844 is the checked phone width | No page-level horizontal scroll; wide tables scroll inside their labelled region; dialogs fit the viewport. |

## 3. Selected focused browser checks

Selected by risk to the user's job (losing an unsaved choice, silently overwriting a newer mapping,
publishing from the wrong model, being stranded on a failed read), not by earlier defect reports. Two
model configurations are exercised: the outgoing System → Master binding in `rdm-systems` and the
incoming Master ← System binding in `rdm-master`, in Live and a named Change set respectively, plus two
installed releases of the starter model.

```sh
PLAYWRIGHT_EXECUTABLE_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
  npm --prefix frontend run test:browser:wp13c
```

`e2e/wp13c-ui-states.mjs` (real backend, 11 checks, 5 scoped axe checks, 12 screenshots; ~8.5 s of
which ~2.4 s harness setup):

1. Coverage read outage keeps the shell and lens, states “Coverage unavailable”, Retry loads the grid.
2. Filtered-empty coverage is explained; clearing the facet restores rows.
3. Keyboard opening of the mapping dialog focuses candidate search; a no-match search is named.
4. Candidate read outage stays inside the dialog; Retry restores candidates.
5. Contextual creation offers every application containing the target type, with the lens's
   application as the default and only its parent types; Cancel keeps the unsaved choice and coverage.
   Creating a master value in RDM Master from the RDM Systems lens selects it and saves it (WP-10F).
6. Explicit save stores the selection and refreshes coverage.
7. A concurrent mapping change shows the current mapping, keeps the attempted choice, blocks Save until
   **Continue with my selection**, then saves the attempted target.
8. Narrow grid and dialog fit 390px, and the candidate search stays ≤ 48px high (WP-10G); Escape
   returns focus to the row action.
9. The inverse binding creates a system value in its only application inside a named change set, maps it,
   and neither the value nor the mapping reaches live.
10. Change-set list outage keeps the page header; Retry loads change sets.
11. A change set created on a non-active release names both releases by key and version (no UUID, WP-10G),
    explains the mismatch and refuses activation.

Outages are simulated with `page.route` 503 responses on one read path until restored; every successful
read and write reaches the real backend. React development mode issues reads twice, so an injected
failure must persist until the Retry click rather than failing once.

## 5. Follow-ups found (delivered as WP-10F/WP-10G on 2026-09-25)

- **WP-10F — Contextual target creation is scoped to the lens's application.** `MappingActionDialog`
  passes the view's `applicationKey` to `ObjectFormDialog`, and objects belong to one application. In
  the starter model the System → Master lens (`rdm-systems`) offers a Codelist parent that its
  application cannot load, and the Master ← System lens (`rdm-master`) cannot create a system value at
  all. Needs a product decision on which application owns a target created in context (the target
  type's owning application, or one chosen from the applications that contain it) and a real-API
  regression.
- **WP-10G — Visual fixes:** narrow candidate-search height; human-readable active release in the change set
  mismatch notice.
